# 插件作者签名与“已验证”发布者（设计稿）

状态：**已审**（2026-11-06，决定见第 7 节），还没有实现。对应 [plugin-platform.md](plugin-platform.md) P11 里写着“以后再做”的两项：可选的作者签名、“已验证”发布者。

## 1. 要防什么

现在的信任链：

```text
岛屿内置公钥 ──签名──▶ focusd-plugins 的 index.json ──SHA-256──▶ 插件 zip
```

索引签名能保证“岛屿装的 zip 就是索引 CI 看到的那个 zip”，但 CI 自己看不出 zip 是不是作者本人发的。剩下的几个风险：

| # | 场景 | 现在会怎样 |
|---|---|---|
| A | 作者的 GitHub 账号或仓库被盗，攻击者发了一个新 Release，权限不变 | 每小时一次的 CI **自动上架**；开了自动更新、又信任这个发布者的用户会**自动装上** |
| B | 同上，但新版本申请了新权限 | CI 暂缓上架并开 `review-needed` issue，靠维护者看出来 |
| C | focusd-plugins 的 CI 密钥泄露，或者有人改了 `main` | 攻击者能给任意 zip 签索引，所有新版岛屿都会接受 |
| D | 冒充：别人起一个看起来像知名开发者或公司的发布者名 | 市场只显示 GitHub 用户名，用户分辨不出来 |

作者签名解决 A，并缓解 C（见第 3.4 节的“首次信任后固定密钥”）。“已验证”发布者解决 D。B 已有人工审核，作者签名能顺便让审核者确认是作者本人发的。

不在本文范围：恶意插件本身（首次上架时由人工审核源码）、用户本机被入侵。

## 2. 参考

- **VS Code**：市场有“已验证发布者”（验证域名，名字旁显示蓝色勾），2024 年起所有扩展包由市场签名、客户端校验，但没有作者签名。
- **npm**：provenance（Sigstore，证明包由某个仓库的 CI 构建），不需要作者管理密钥，但依赖 Sigstore 的在线服务和 OIDC。
- **Android / Chrome Web Store（开发者签名）**：安装后固定开发者密钥，换密钥要用旧密钥签一份证明，否则不能覆盖安装。下面的 3.4、3.5 节参考这一点。
- **minisign / signify**：单文件 Ed25519 签名，工具简单。我们的索引签名已经是 Ed25519，作者签名沿用同一套代码。

没选 Sigstore：要多依赖一个在线服务，离线校验麻烦，而且只能证明“这个仓库的 CI 构建的”，仓库被盗时同样能伪造。作者自己保管的密钥正好能防仓库被盗。

## 3. 作者签名

### 3.1 密钥与签名格式

- 算法：Ed25519，和索引签名一样（`plugin_host/signature.rs`、`scripts/plugins/plugin-signing.mjs` 的代码可以复用）。
- 公钥写法：`{ "keyId": "<公钥 SHA-256 的前 16 个十六进制字符>", "publicKey": "<32 字节，base64>" }`，和 `plugins/signing-keys.json` 一致。
- 签名对象不是 zip 本身，而是一段带域名分隔的文本，防止把 A 插件的签名挪到 B 插件、或者把旧版本的签名挪到新版本：

  ```text
  focusd-plugin-package/1
  <插件 id>
  <版本>
  <zip 的 SHA-256，小写十六进制>
  ```

- 签名文件：Release 里与 zip 并列的 `<id>-<version>.zip.sig`，内容 `{ "keyId", "signature" }`（和 `index.json.sig` 同样的形状）。不放进 zip 里，因为 zip 的哈希必须在签名之前确定。

### 3.2 作者怎么用（SDK）

`fly-island-plugin` 新增：

| 命令 | 作用 |
|---|---|
| `fly-island-plugin keygen` | 生成密钥对。私钥存在用户目录（Windows 下用 DPAPI 加密，和 `pnpm plugins:keygen` 一样），打印公钥和 keyId，提醒备份 |
| `fly-island-plugin pack --sign` | 打包后在 `.package/` 里同时写出 `.zip.sig` |
| `fly-island-plugin sign <zip>` | 给已有的 zip 补签名 |
| `fly-island-plugin keys rotate` | 换密钥：生成新密钥，并用旧密钥签一份“新密钥由我认可”的证明（见 3.5） |

私钥也可以用环境变量 `FLY_ISLAND_PLUGIN_SIGNING_KEY`（PEM）提供，方便在作者自己的 CI 里签。文档要写清楚：放在作者 CI 里的密钥和仓库一起被盗的风险更高，最安全的是本机签好再上传。

### 3.3 登记与索引 CI（focusd-plugins）

- 提交文件 `plugins/<id>.json` 新增可选字段：

  ```json
  "signingKeys": [{ "keyId": "…", "publicKey": "…" }]
  ```

  只能通过维护者审核的 PR 修改。第一次登记时，PR 检查会要求最新 Release 已经带着用这把密钥签的 `.zip.sig`，证明提交者确实持有私钥。
- `Update index` 的新规则：
  - 提交里**没有** `signingKeys`：和现在一样。
  - 提交里**有** `signingKeys`：新 Release 必须带有效的 `.zip.sig`，并且由登记的某把密钥签名。没有签名或签名不对的版本**一律不自动上架**，开 `review-needed` issue（原因写“缺少作者签名”或“签名无效”），即使维护者写了 `approved` 也不能让无签名的版本上架；作者丢了密钥的处理见 3.5。
  - 签名通过的版本，索引条目新增：

    ```json
    "authorSignature": { "keyId": "…", "signature": "…" },
    "authorKeys": [{ "keyId": "…", "publicKey": "…" }]
    ```

    `authorKeys` 是这个插件当前登记的公钥（含换密钥证明，见 3.5），跟着索引一起签名。
- 已上架的版本不会补签名，也不会去掉签名：条目里的签名和版本一起固定。

### 3.4 岛屿怎么校验

安装和更新时，在现有的“索引签名 → SHA-256 → 解压检查”之外增加：

1. 条目带 `authorSignature` 时，用 `authorKeys` 里对应的公钥校验 3.1 节的签名对象；不通过就拒绝安装（和 SHA-256 不对一样处理）。
2. **首次信任后固定密钥**：第一次安装带签名的插件时，把 `authorKeys` 的 keyId 记进 `plugins.json` 的 `plugins.<id>.authorKeys`。之后的更新：
   - 由已记下的密钥签名 → 正常更新（自动更新照常）。
   - 由新密钥签名，但 `authorKeys` 里有已记下密钥签的换密钥证明 → 正常更新，并把新 keyId 记下。
   - 没有签名，或者签名的密钥既不是已记下的、也没有旧密钥的证明 → **不自动更新**。卡片显示“这个版本的签名密钥变了”，用户要在插件设置页点“仍然更新”并再次确认（两次确认）才会安装，确认后改记新密钥（没有签名时清空记下的密钥）。
3. 这样即使 C 场景发生（索引密钥泄露、攻击者在索引里换了 `authorKeys`），已经装了这个插件的用户也不会被自动更新成恶意版本。新装的用户不受这一条保护（首次安装只能信任索引），这是首次信任的固有局限。
4. 开发模式加载的插件、手动放进插件目录的插件不检查作者签名。
5. **自动更新只给签了名的插件**：在现有条件（可信发布者、不申请新权限）之外，新版本还必须带有效的作者签名，并且签名密钥是已记下的密钥（或有它签的换密钥证明）。不满足时只在卡片上提示“有新版本”，由用户手动更新。设置里「自动更新插件」的说明同步改成“只自动安装作者签名、来自可信发布者且不申请新权限的更新”。

市场和插件卡片上：带签名的插件显示“作者已签名”（鼠标悬停显示 keyId）。不签名的插件不显示警告（签名是可选的），只是不会自动更新。

### 3.5 换密钥与丢失密钥

- **换密钥（旧密钥还在）**：`fly-island-plugin keys rotate` 输出一份证明

  ```json
  { "keyId": "<新>", "publicKey": "<新>", "endorsedBy": { "keyId": "<旧>", "signature": "<旧私钥对 'focusd-plugin-key/1\n<插件 id>\n<新 keyId>\n<新公钥>' 的签名>" } }
  ```

  作者开 PR 把它加进 `signingKeys`。CI 校验证明后写进索引的 `authorKeys`。岛屿按 3.4 第 2 条自动接受新密钥。旧密钥可以保留一段时间再删。
- **丢了密钥**：作者开 PR，在 `signingKeys` 里换成新公钥（没有证明）。维护者需要另外核实身份（例如作者在插件仓库的 issue 里用同一个 GitHub 账号说明，并且仓库最近没有异常提交）后才合并。已安装的用户会看到“签名密钥变了”，要手动确认。这一步故意麻烦，因为它和“仓库被盗后攻击者换密钥”在岛屿看来完全一样。
- **想停用签名**：同样走维护者审核，并且同样会让已安装用户看到“签名密钥变了”（之后的版本没有签名）。

### 3.6 官方插件

官方插件（`dev.focusd.*`）可以用同一套机制：生成一把官方作者密钥，`pnpm plugins:index` 打包时同时签名，focusd-plugins 里的官方提交登记它。本仓库的旧索引不需要这个字段（旧版岛屿也看不懂）。**第一期必须给官方插件签上**：自动更新只给签了名的插件（3.4 第 5 条），不签的话官方插件也会失去自动更新。官方作者密钥和索引签名密钥分开保管，丢失或泄露其中一把不影响另一把。

## 4. “已验证”发布者

目的只是让用户分清“真的是这个组织/这个人”，不代表插件安全。

两种来源，满足任一即可：

1. **GitHub 已验证域名的组织**：GitHub API 的组织信息里有 `is_verified` 和已验证的域名。发布者是组织且 `is_verified` 为真时，标记为已验证，显示其域名。不用作者做任何事。
2. **个人或没有验证域名的组织**：在自己的域名下放 `https://<域名>/.well-known/focusd-publisher.json`，内容 `{ "github": "<发布者名>" }`，并在提交里写 `"domain": "<域名>"`。CI 检查文件内容和发布者一致。

- 索引 CI 每天重新检查一次；失效（文件没了、组织不再验证）就去掉标记，并在 Actions 摘要里报告。
- 索引条目新增 `"verifiedDomain": "<域名>"`，岛屿在发布者名旁显示“已验证 · <域名>”。官方发布者继续显示“官方”。
- 域名只显示，岛屿不去访问它（索引签名已经保证这个字段是 CI 写的）。

## 5. 兼容性

- 新字段（`authorSignature`、`authorKeys`、`verifiedDomain`）只出现在 focusd-plugins 的索引里。岛屿的 `MarketEntry` 没有 `deny_unknown_fields`，不认识这些字段的岛屿会忽略它们，照常安装（也就没有作者签名的保护）。
- 本仓库给旧版岛屿的 `plugins/index.json` 不加这些字段。
- `plugins.json` 新增 `plugins.<id>.authorKeys`，旧数据没有这个字段时视为“还没记下”，下次安装/更新带签名的版本时记下。属于对外契约的新增字段，不改旧字段。
- 协议（`rpc.json`）和插件清单都不变，插件代码不需要改。

## 6. 分期

| 期 | 内容 | 涉及 |
|---|---|---|
| 1 | 签名格式；SDK `keygen` / `pack --sign` / `sign`；focusd-plugins 的登记、CI 校验、索引字段；岛屿校验、首次信任后固定密钥、“签名密钥变了”提示与确认、“作者已签名”标签；官方插件签名 | `packages/fly-island-plugin`、focusd-plugins `scripts/`、`plugin_host/{market,signature,updates,store}.rs`、`src/features/plugins/` |
| 2 | 换密钥证明（`keys rotate`、CI 校验、岛屿自动接受） | 同上 |
| 3 | “已验证”发布者 | focusd-plugins CI、市场页 |

第 1 期之前不需要发岛屿版本：岛屿端的改动随下一个版本发布即可，在那之前已上架的签名版本照常能装（旧岛屿忽略签名）。第 1 期的顺序：先让 focusd-plugins 的索引带上官方插件的签名，再合入岛屿端的“只给签名插件自动更新”，避免中间有一段时间官方插件也不能自动更新。

## 7. 决定（2026-11-06）

1. **作者签名可选**，第一期不强制。以后可以对申请敏感权限的插件强制。
2. **签名密钥变了时，用户能自己确认更新**，要确认两次（3.4 第 2 条）。作者丢了密钥时用户不必卸载重装。
3. **只有签了名的插件才自动更新**（3.4 第 5 条）。没签名的插件只提示有新版本。官方插件因此必须在第一期签上（3.6）。
4. **“已验证”发布者要做**，排在第 3 期（第 4 节）。
