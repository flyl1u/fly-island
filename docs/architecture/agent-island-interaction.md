## 二、技术上能做到什么（已查官方文档）

### Claude Code

依据 [hooks 参考](https://code.claude.com/docs/en/hooks)：

- **审批**：`PermissionRequest` 钩子在 Claude Code 要弹审批框前触发，输入里有 `tool_name`、`tool_input`（Bash 的 `command`、`description` 等）和 `permission_suggestions`（Claude Code 建议的「始终允许」规则）。钩子返回 `hookSpecificOutput.decision`：
  - `behavior: "allow"` = 允许一次；
  - `behavior: "deny"` 加 `message` = 拒绝，`interrupt: true` 还能让 Claude 停下；
  - `"allow"` 加 `updatedPermissions`（把收到的某条 `permission_suggestions` 原样传回）= **始终允许**，`destination` 可以是只在本次会话 `session`，或写进 `localSettings` 等；
  - `updatedPermissions` 里的 `setMode` 可以切换权限模式（如 `acceptEdits`、`auto`），对应参考软件的「自动批准」。
  - 不返回决定（空输出），就照常走终端的审批框。用户在 settings 里写的 deny 规则仍然优先，钩子越不过去。
- **回答提问**：`AskUserQuestion` 工具触发 `PreToolUse` 钩子，输入是 1～4 个问题（`question`、`header`、`options`、`multiSelect`）。钩子返回 `permissionDecision: "allow"` 并在 `updatedInput` 里原样带回 `questions`、再加上 `answers`（问题文字 → 选中的选项名，多选用逗号连接），Claude Code 就不再问用户。文档明确说这是给「用你自己的界面收集答案」准备的。
- **完成**：`Stop` 钩子的 `last_assistant_message` 就是最后一条回复的文字，完成卡片直接用它，不用读会话文件。`StopFailure` 带 `error`。
- **HTTP 钩子**：钩子可以是 `type: "http"`，Claude Code 把事件 JSON POST 到指定地址，响应体就是钩子输出，可以带 `headers`。**岛屿没运行时连接失败，按非阻塞错误处理，操作照常进行，审批框照常出现**，所以不会因为岛屿关了而卡住 Agent。默认超时 600 秒。
- 企业管理的 `allowedHttpHookUrls` 可能禁用 HTTP 钩子，这时退回到现在的 PowerShell 钩子（只通知，不在岛上审批）。

### Codex

依据 [Codex hooks 文档](https://learn.chatgpt.com/docs/hooks)：

- `PermissionRequest` 可以返回 `decision.behavior` 为 `"allow"` 或 `"deny"`（带 `message`）；不返回决定就走正常审批。**没有「始终允许」**，文档明确说不要返回 `updatedPermissions`。
- `Stop` 有 `last_assistant_message`。
- **钩子没有办法回答模型的提问**。Codex 的提问只能做成提醒卡片加「跳到终端」。

### 必须先实测的问题

文档没写清楚，开工前在本机各跑一次（第 0 期）：

1. **钩子等待时，终端里的审批框是否同时显示？** 如果要等钩子返回才显示，那在岛上没点之前终端也没法操作。届时需要：岛上有「到终端处理」按钮（立即返回空决定）；可设的等待上限（例如 60 秒，到时返回空决定，审批框出现）；终端标签在前台时立即返回空决定。Codex 同样要测。
2. **在终端里先回答了会怎样？** 如果审批框和钩子同时存在，用户在终端点了之后，钩子的请求是否被取消（HTTP 连接断开）。岛上要据此把卡片撤掉。
3. **回答框里的自由文本**：`answers` 填一个不在选项里的字符串，Claude Code 是否当作「其他」接受。不行的话，输入框只在 Claude Code 自己提供「其他」时显示。
4. **AskUserQuestion 的 PreToolUse 钩子是否也阻塞终端里的选项界面**，同第 1 条。
5. Windows 上 HTTP 钩子到 `127.0.0.1` 的延迟和稳定性；岛屿重启后旧连接怎么处理。

**实测结论（2026-11-06，Claude Code 2.1.318，详见任务清单的「实测记录」）**：

- 第 1、4 条：都会阻塞。钩子返回前终端既不显示审批框，也不显示选项，所以「到终端处理」、等待上限和「终端在前台时直接交还」都必须做。auto 模式自己批准的命令不会触发 `PermissionRequest`。
- 第 2 条：因为终端在等待期间没有审批框，不存在先在终端回答的情况。用户按 Esc 时连接立即断开，岛上据此撤掉卡片。
  - **2026-11-07 更正（Claude Code 2.1.319，B6.2.7）**：现在钩子等待时终端也会显示审批框。用户在终端答了之后，Claude Code 照常往下执行，但**不关闭**钩子的连接，岛上的卡片就一直留着，直到 2 分钟的等待上限。修法：「安装/修复」额外在 `PostToolUse`、`PostToolUseFailure`、`PermissionDenied`、`Stop`、`SubagentStop`、`UserPromptSubmit` 上装一个后台运行的 `curl.exe` 钩子，把钩子输入发到 `POST /claude/activity`。会话有了这些动静，就说明它等的审批已经在别处答过了：工具调用按会话、子 Agent、工具名和参数找到对应的请求；一轮结束则找出这个 Agent 的全部请求。岛屿撤掉对应的卡片（关闭原因 `answeredElsewhere`），并给挂着的连接回 `{}`。Codex 的钩子在等待时仍然挡住终端，不受影响。
- 第 3 条：不在选项里的文字原样接受，输入框可以一直显示。
- 第 4 条补充：`AskUserQuestion` 在 `PreToolUse` 返回空决定后还会再触发一次 `PermissionRequest`。岛上不处理这个提问时，这一次要立即返回空决定。用 `PreToolUse` 回答后不会再触发。
- 第 5 条：延迟可忽略；岛屿没运行时连接失败，审批框立即出现。
- Codex 还没测，做第 2 期的 Codex 部分前补测。

## 三、设计

### 1. 通道：岛屿上的本机 HTTP 端点

- 新开一个只听 `127.0.0.1` 的端点，专门接 Agent 钩子，不复用插件的本地接口（那个由内置插件开关控制，用户可能关掉）。端口固定一个默认值，被占用时换一个，安装钩子时把实际地址写进配置，岛屿启动时发现端口变了就提示「安装/修复」。
- 鉴权：安装钩子时生成一个随机令牌，写进 Claude Code 配置的 `headers`；岛屿只接受带这个令牌的请求。令牌和端口一样保存在应用数据目录。
- 安装：在现有的「安装/修复」里，为 Claude Code 增加 `PermissionRequest`（HTTP）和 `PreToolUse` 只匹配 `AskUserQuestion`（HTTP）两项；现有的 PowerShell 状态钩子保留。Codex 只加 `PermissionRequest`。是否启用「在岛上审批」是一个开关（默认关）。实现时改为：钩子总是随「安装/修复」装上，开关只决定端点是否挂起请求，关着时端点立即返回空决定，终端照常审批；这样开关切换不用重装钩子，也不用重启 Agent。Codex 没有 HTTP 钩子，用 `focusd-agent-approval.ps1` 转发，它每次运行时读 `agent-approval.json`，端口变了也不用重装。
- 等待中的请求在 Rust 侧按会话排队，前端只收事件、发决定（Tauri 命令）。岛屿退出时所有等待的请求立即返回空决定。

### 2. 岛上的卡片

一张卡片 = 一个等待处理的事件，同一会话只保留最新一张。其他会话照常列在下面。

| 卡片 | 内容 | 操作 |
|---|---|---|
| 审批 | 会话名、最近一次提问、操作说明、命令或文件路径预览（长命令可展开） | 拒绝 / 允许一次 / 始终允许（Claude Code，且有建议规则时）/ 到终端处理 |
| 提问 | 问题、编号选项和说明、多选时的勾选与提交、可选的输入框 | 选择即提交；到终端处理 |
| 完成 | 会话名、最后一条回复的前几行 | 跳到终端；停留到时自动收起 |
| 出错 | 错误类型和说明 | 跳到终端 |

- 「自动批准」（切换权限模式）风险大，第一版不放在卡片上；如果要做，放在卡片的「更多」里并二次确认。
- 卡片在折叠态也要能弹出：岛屿展开到卡片大小，处理完收回。贴边隐藏时先露出。
- 快捷键：卡片显示时注册（例如 Ctrl+Y 允许、Ctrl+N 拒绝、数字键选项、Ctrl+T 跳到终端），卡片消失时注销，不长期占用全局快捷键。具体按键在快捷键页可改。

### 3. 什么时候弹出

- 默认：审批和提问弹出；完成和出错弹出并停留 5 秒（可设）。每种都能单独关闭，改成只出声或只在折叠条上提示。
- 不弹的情况：会话所在的终端标签或窗口在前台；游戏模式勿扰生效时；用户正在岛上的输入框里打字时（排队，打完再弹）。
- 同时有多个等待：按到达顺序排队，卡片上显示「还有 N 个」。

### 4. 音效

- 前端播放（岛屿窗口里的 `Audio`），不需要原生代码。
- 事件：会话开始、完成、出错、需要审批、需要回答、你发了消息（`UserPromptSubmit`）、上下文快满（`PreCompact`）。额度类事件随 B4 再加。
- 每个事件可选音效或「无」，可试听；总音量；静音时段（跨午夜）；游戏模式和智能抑制时也不响。
- 内置一套**原创**短音效（自己合成或用 CC0 素材，登记来源和许可）；支持导入自己的 `.wav` / `.mp3`，复制到应用数据目录。
- 设置页新开「声音」页，用新的分组列表组件。

## 五、风险

- **安全**：在岛上点「允许」等于替用户批准命令。端点只听本机、要令牌；卡片上必须显示完整命令（可展开），不能只显示 Claude 写的说明；deny 规则仍由 Claude Code 自己执行。「始终允许」默认只写 `session`，写进配置文件要用户在设置里另外选。
- **卡住 Agent**：任何异常（岛屿崩溃、端口错、超时）都必须退回终端审批，不能让 Agent 无限等待。
- **误点**：卡片在用户打字时突然弹出，按键可能误触按钮。卡片出现后的前 0.5 秒不接受点击和快捷键。
- **接口变化**：Claude Code 和 Codex 的钩子仍在快速变化。钩子输出只用文档写明的字段；安装时记录 Agent 版本，太旧的版本不装 HTTP 钩子。
