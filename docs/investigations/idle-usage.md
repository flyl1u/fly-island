# 空闲时的 CPU 和内存（路线图 D1）

2026-11-06，fly-island-fe（lane 4）。

## 测法

- 构建：`pnpm tauri build --debug --no-bundle`，加 `CARGO_PROFILE_DEV_OPT_LEVEL=3`、`CARGO_PROFILE_DEV_DEBUG=0`。前端是正式打包的产物，Rust 按 release 的级别优化，CPU 接近正式版。用 debug 构建是为了能带 `FOCUSD_DEV_LANE=4` 以 `com.focusd.island.lane-4` 的身份运行：单独的数据目录和单实例锁，可以和用户正在用的岛屿同时开，默认设置、没有插件。
- 统计：岛屿进程和它启动的全部子进程（WebView2、插件），启动 20 秒后采样 60 秒，CPU 为这 60 秒里占用的处理器时间除以 60 秒（单核占比）。私有内存为 `PrivateMemorySize64`，工作集为 `WorkingSet64`，WebView2 的数字每次相差几十 MB。
- 机器：Windows 11，20 个逻辑核，WebView2 156。

## 结果（收起、闲着）

| | CPU（单核） | 私有内存 | 工作集 |
|---|---|---|---|
| 优化前，在放音乐 | 24% | 284 MB | 606 MB |
| `cef6251` 后，不放音乐 | 15% | 376 MB | 653 MB |
| `376c9cb` 后，不放音乐 | **10%** | **330 MB** | 634 MB |

`376c9cb` 后各进程：Rust 主进程 4.9%、16 MB；WebView2 合计约 5%，其余内存都在 WebView2。用户本机装的 4 个示例插件（PowerShell）各占约 63 MB 私有内存、CPU 几乎为 0。

## 各项定时读取（release 构建，单次耗时）

| 读取 | 单次 | 频率 | 单核占比 |
|---|---|---|---|
| Agent 会话列表（8 个会话） | 1.2 ms | 每秒 | 0.12% |
| Claude 用量快照 | 0.05 ms | 30 秒 | 可忽略 |
| 系统音量峰值 | 3.6 ms | 0.5 秒，只在播放时（`cef6251` 前一直在读） | 0.7% |
| 媒体状态 | 5.5 ms | 1.5 秒 | 0.4% |

媒体的两项贵，是因为每次都新开一个线程并初始化 COM（`media_control/session.rs` 的 `on_media_thread`）。改成常驻线程能再省，但一次卡住的读取会堵住之后所有读取，暂未做。

## 做了的优化

- `cef6251`：收起岛屿上的音乐按钮只在播放时动（以前播放器暂停时也每 180 ms 重绘），播放时 10 帧/秒；0.5 秒的音量读取只在播放时运行。
- `376c9cb`：鼠标穿透循环（每 12 ms）每次调用的 `window.hwnd()` 在 Tauri 里要和主事件循环往返一次，主线程每秒被叫醒约 83 次；改为循环开始前取一次。

## 还能做的

- 鼠标穿透循环在光标离岛屿很远时放慢（例如 50 ms）。会影响光标移进岛屿时的反应，要实际试手感。
- 媒体读取改成常驻线程，见上。
