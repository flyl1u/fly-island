# 贴边露出位置排查（2026-11-19）

目标：悬停或消息露出回到贴边前的位置；原本贴顶时贴顶，正常悬浮时保留自定义位置。

| 路径 | 核实结论与处理 |
|---|---|
| (a) 自定义 y 过期 | `resolve_stage_position` 露出时直接采用 `custom_position.y`。`record_dragged_position` 只在 `is_dragging && !is_tucked` 时更新，所以系统在非拖动期间重新安置窗口后，缓存可以与实际正常位置不同。单测注入“缓存在顶边下 180px、实际在顶边”的状态，旧解析确实返回偏下的 y。现在首次进入贴边前校准实际位置，同时用已有位置事件同步前端持久化；首次恢复存档、没有自定义位置、拖动进行中均不采样。没有把正常悬浮的 y 强制归零。 |
| (b) 顶部任务栏 / 工作区 | 收起与正常位置共用 `monitor.position.y + monitor_top_inset`，Windows 顶部任务栏的偏移已是物理像素，不再乘 DPI。第三方工作区保留带不参与该偏移（既有约定）。将这段实际生产计算提取为 `stage_top_positions` 并覆盖无任务栏 / 顶部任务栏、不同显示器原点；未发现重复偏移。 |
| (c) 多显示器与 DPI | 自定义位置、观测位置和动画终点均保留物理坐标。新增矩阵覆盖负原点 / 下移的显示器，100% / 125% / 150% / 175% 与顶部任务栏；正常终点没有再次缩放。真实 Windows 的显示器切换、WM_DPICHANGED 和显示器归属仍需实机验收，不能据纯几何测试声称已复现视频的唯一触发条件。 |
| (d) 窗口 / 舞台高度 | 舞台 CSS 在上沿布局；Rust 舞台只因内容增长而变高，正常位置解析不引用舞台高度。矩阵覆盖面板 220 / 450 / 800px、展开与消息尺寸，终点上沿一致。没有新增高度补偿。 |
| (e) 折叠缩放 | 折叠缩放只影响露边距离 / 热区，不参与正常 y。矩阵覆盖 0.75 / 1.0 / 1.4 和露边 / 细线 / 隐藏。保留现有换算，未增加缩放补偿。 |

额外复现：露出动画尚在运行时再次收回，若直接把观测位置当作正常位置，就会把中间帧存下来。校准优先使用当前代动画的终点，忽略已失效代的动画。新增测试覆盖这一路径及正常悬浮位置保持。

正常拖动结束会等待左键释放，调用 `snap_to_top`，再写入并发出最终自定义位置；未发现一条“拖到顶边即直接贴边、必然保存偏下 y”的独立路径。因此不能把普通悬浮位置的 y 当成错误数据，也不能无条件把全部旧位置重置到顶部。

没有用户视频对应的显示器布局、缩放和运行态日志，无法证明视频只由某一条路径触发。本次修复解决可用测试证明的过期坐标和动画中间帧路径；未新增 IPC、localStorage key 或数据格式。

实机验收：在单屏与混合缩放双屏上分别把岛拖到顶边 / 悬浮位置，贴边后用悬停和新消息露出；尝试快速往返、面板高度变化、顶部任务栏，以及切换缩放后再贴边。折叠、展开、托盘隐藏 / 恢复均应保留正常位置。
