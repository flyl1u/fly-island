# 邮箱接入

支持一个邮箱：QQ 邮箱，以及 163、126 和多数学校、公司邮箱等 IMAP 服务器为 `imap.<邮箱域名>` 的邮箱。使用本机直连 IMAP（端口 993，TLS），无需额外服务器或 Windows 通知访问权限，也不依赖 QQ 客户端运行。

## 首次连接

1. 打开邮箱网页，在邮箱设置中开启 IMAP，按提示验证身份并生成授权码。具体设置位置以各邮箱当前界面为准；QQ 邮箱可在 [QQ 邮箱帮助中心](https://service.mail.qq.com/) 搜索「IMAP」或「授权码」，面板上的帮助按钮也只在 QQ 邮箱地址时显示。
2. 展开岛屿，点击消息按钮，选择「邮箱」。
3. 填写邮箱地址和授权码，点击「连接邮箱」。授权码与邮箱登录密码不同。服务器地址按邮箱域名推导为 `imap.<域名>`，暂不能手动填写。

163、126 等网易 Coremail 邮箱要求登录后先发送 RFC 2971 `ID` 命令，否则拒绝打开收件箱（"Unsafe Login"）。服务器声明支持 `ID` 时，应用在登录后发送一次客户端标识（名称 `fly-island`，不含任何账号信息）。这部分移植自 flyl1u/fly-island#39（作者 ShengLin1001）。

连接成功后优先使用 IMAP IDLE 监听服务器变化，新邮件到达即可触发同步，并每 60 秒校准一次收件箱；服务器不支持或拒绝 IDLE 时自动回退到每 5 秒检查，可随时手动刷新。列表展示最近 20 封邮件，已下载的邮件头在本次连接中缓存，只补取新邮件的邮件头；未读总数通过 STATUS 查询整个收件箱，不枚举全部未读邮件。点开某封邮件时才读取正文，不下载附件，不改变邮箱已读状态。

手动刷新、暂停和断开会中断后台推送等待，不必等到校准周期结束。同步过程中到达的新邮件会触发立即补查，避免进入推送等待后漏掉已发生的变化。后台等待结束与重连均有超时保护。

首次连接、每次启动、暂停后恢复接收时只建立邮件基线，不弹出历史邮件提醒。此后新到且未读的邮件会在折叠岛上预览 5 秒，连续消息最多预览 10 秒；与 QQ、微信提醒按到达时间共享预览位置。展开、边缘收起或托盘隐藏时不主动展开、抢焦点。

折叠态的邮件图标点击进入邮箱列表；点击邮件预览或邮箱列表项，会在岛内打开该封邮件的阅读页。「返回列表」回到邮箱列表，并恢复滚动位置。「在网页打开」打开 `https://mail.<域名>/` 网页入口（QQ、Foxmail 地址打开 QQ 邮箱），用于处理附件和回复；浏览器未登录时需先登录，不保证直接定位到某一封邮件。

## 岛内正文阅读

- 阅读页显示主题、发件人、时间和可滚动正文；加载失败可原地重试，也可返回列表或打开网页版。
- 使用 `EXAMINE` 和按 UID 的 `BODY.PEEK` 只读请求。每次核对 `UIDVALIDITY`，避免收件箱重建后读取同 UID 的其他邮件。
- 从 MIME 结构选择非附件的文字部分，优先纯文本，缺少纯文本时使用 HTML；支持 Base64、Quoted-Printable 和中文字符集解码。不会获取附件部分或转发邮件的独立附件正文。
- 单个编码后的文字部分最多 512 KB，过大或无法解析时提示在网页查看。正文只保留在本次阅读的内存状态中，不写入文件或 `localStorage`。
- HTML 正文通过 DOMPurify 的标签、属性和 URL 白名单清理，移除脚本、样式、表单、嵌入内容、图片和资源加载属性。保留段落、列表、表格和 HTTP/HTTPS 链接；链接由用户点击后交给默认浏览器打开。
- 返回、切换邮件、断开连接或更换账号会使旧阅读请求失效，旧响应不会覆盖当前页面或重新显示已清空的正文。阅读期间不自动标为已读，未读数保持服务端状态。

## 保存与恢复

- 授权码仅保存到 Windows 凭据管理器，服务名为 `com.focusd.island.qq-mail`，账号为邮箱地址；前端不读取已保存的授权码。
- `focusd-island-qq-mail-settings` 只保存邮箱地址和接收开关。邮件列表仅驻留内存，退出清空；下次启动从邮箱重新加载。
- 暂停接收保留凭据和本次运行的最近结果，恢复后重新建立基线。断开连接会停止检查、清空邮箱状态并删除凭据。
- 网络错误保留上次数据和同步时间，以 5、15、30、60、120、300 秒退避重试，后续最多等待 300 秒。授权码失效或 IMAP 未开启时停止自动重试，在表单中重新连接。
- 暂不支持多个账号、自定义 IMAP 服务器地址（服务器不是 `imap.<域名>` 的邮箱，例如部分企业邮箱和 Foxmail，暂时无法连接）、附件预览、标记已读或发送邮件。

## 验证

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --lib qq_mail::tests
node --test tests/unit/qq-notification-timing.test.mjs tests/unit/message-preview.test.mjs
pnpm build
pnpm tauri build --no-bundle
```

协议测试使用模拟 IMAP 响应检查只读命令、中文邮件头、完整未读数、空收件箱、去重、UID 重置和过期请求。真实收件需要在本机界面输入有效授权码后验收；模拟协议、界面检查和构建不等同于真实邮箱连接成功。

正文协议测试另外覆盖只读按需获取、中文正文解码、嵌套 MIME、纯文本优先、跳过附件、正文大小上限、UID 有效性变化，以及不完整或格式不匹配的正文。

运行 `pnpm dev` 后打开 `/tests/regression/mail-reader.html?run=1`，可运行真实 React 组件与模拟 Tauri 边界的导航和阅读回归检查。`?state=qq`、`wechat`、`empty`、`disconnected`、`reader`、`html`、`loading`、`error`、`auth`、`wechatError` 可预览各状态；夹具不使用真实账号，不操作微信或 QQ。

## 本机验证记录（2026-10-19）

- Rust 邮箱模块 9 项测试、前端预览与角标 5 项测试通过；`pnpm build` 和 `pnpm tauri build --no-bundle` 通过。
- 独立 Edge 测试浏览器使用真实 React 界面和模拟 Tauri 边界，最终连续 3 轮通过。覆盖授权失败保留输入、暂停偏好恢复、断网保留列表、自动恢复后清除错误、三来源预览、展开或隐藏时不预览、最窄折叠宽度，以及连接过程中断开后清除输入并忽略旧响应；检查了普通与 2 倍像素密度截图。
- 界面复核发现并修复认证失败态主操作被裁切的问题，复核确认授权码输入、帮助入口和重连按钮完整显示。
- 本机到 `imap.qq.com:993` 的证书验证、TLS 1.3 握手和 IMAP 欢迎响应通过，未发送登录凭据。
- 未使用真实授权码，因此真实账号认证、收件、凭据实际写入与删除，以及原生托盘隐藏的完整交互仍需在桌面版验收。
- `imap 2.4` 的间接依赖 `imap-proto 0.10.2` 存在未来 Rust 版本兼容性警告，不影响当前构建；后续升级 Rust 时需关注。
