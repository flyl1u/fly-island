# 文件中转

把文件临时放在岛上，换到别的窗口后再拖出去、复制或打开。适合"从资源管理器拿一个文件，切到微信 / QQ / 另一个文件夹再放下"这种来回切窗口的场景。

## 用法

- **放进来**：把文件或文件夹从资源管理器拖到岛上。岛会展开到文件中转页作为投放区，松手即加入；没放下就移开，岛恢复原来的状态（折叠、贴边收起或原来的页面）。也可以拖到贴边收起时露出的那条边上。
- **拿出去**：在条目上按住鼠标直接拖到资源管理器、桌面、微信、QQ 等应用。默认直接复制到目标位置，原文件不动，岛内条目也保留，可以重复拖出；不需要再按 Ctrl+V。拖动时按住 Shift 变为移动，与资源管理器一致；源文件移走后按失效条目规则处理。
- **多选**：按住 Ctrl 点击逐个选择，按住 Shift 点击选择一段；从任意已选条目开始拖，会把所选的文件一起拖出。选中两个以上时顶部出现选择栏，可一次复制或移除。点击列表空白处取消选择。
- **其他操作**：每个条目可以复制（之后在任意位置 Ctrl+V 粘贴）、在文件夹中显示、置顶、从列表移除；双击打开文件。
- **搜索**：标题右侧的搜索框按文件名或路径过滤，不区分大小写和斜杠方向。
- **置顶**：置顶的条目固定在最上面，不会被自动清理，也不计入最多保留条数。

## 只存路径，不复制文件

列表只记录文件路径，文件本身不会被复制或移动；移除条目、清空列表、自动清理都只改列表，不会删除你的文件。

因此源文件被移动、改名或删除后，条目显示「已失效」，不能再拖出或复制。如果文件所在的网络共享或 U 盘暂时连不上，条目显示「无法访问」：每个磁盘或共享最多等 300 毫秒，没响应的 30 秒内不再检查，避免列表卡住；「自动移除已失效的文件」不会移除这类条目。

## 设置

「设置 → 剪贴板与文件 → 文件中转」：

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用文件中转 | 开 | 关闭后岛上不再显示入口，列表保留 |
| 自动清理 | 从不 | 加入超过 1 / 7 / 30 天的条目自动移出列表（置顶的除外） |

其余行为固定为：拖入自动展开、双击打开、折叠时显示文件数量、自动移除确定失效的条目、最多保留 100 条、拖出后保留。旧设置里的 `shelfRemoveAfterDragOut: true` 也会读取为 `false`，避免用户留下一个无法在设置页改回的移除行为。

## 限制

- 只能放文件和文件夹。从浏览器拖来的文字、网页图片等没有文件路径的内容，系统不会把它交给岛，所以拖进来没有反应。
- 图片（PNG、JPEG、GIF、WebP、BMP，40 MB 以内）显示缩略图，其他文件显示资源管理器里的图标（48px 系统图标，命令 `get_file_shelf_icon`）。同类型文件共用一个图标，只按扩展名向系统要，不读文件本身，所以断开的网络盘也不会卡住；程序、快捷方式（exe、lnk、ico、url 等）用文件自己的图标，只在文件可访问时读取。拿不到系统图标时（或在 Windows 之外）显示按类型着色的 lucide 图标。

## 实现

| 部分 | 位置 |
|---|---|
| 列表、清理规则、命令 | `src-tauri/src/file_shelf/`（`mod.rs` 命令，`store.rs` 读写与规则，`availability.rs` 按卷检查是否可访问，`thumbnail.rs` 缩略图，`icon.rs` 系统图标；取图标的 Win32 调用在 `win32/icon.rs`） |
| 拖出 | `src-tauri/src/win32/ole.rs`：`SHDoDragDrop` + 资源管理器自己的数据对象。允许复制、移动、链接，首选复制。只允许复制时资源管理器会拒绝投放，这是没有直接用 `drag` crate 的原因 |
| 复制到剪贴板 | `clipboard-win` 写入文件列表（CF_HDROP），与资源管理器的复制相同 |
| 拖入 | Tauri 的 `onDragDropEvent`，`src/windows/island/useFileShelfDrop.ts` |
| 页面 | `src/features/file-shelf/` |

列表保存在应用数据目录的 `file-shelf.json`。清理设置不写进这个文件：岛启动时通过 `set_file_shelf_options` 发给后端，之后每次读取或修改列表都会按它清理，所以不需要定时器。除添加外，命令只接收条目 id，只会把已在列表中的路径交给系统。
