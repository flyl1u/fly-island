# 截图插件：安装、配置与后续能力

2026-11-26 用户确认：截图在插件市场独立安装、独立启停，安装后提供设置入口；默认 Alt+A，支持改键。长截图和录屏只标注“开发中”。本阶段不实现这两种捕获能力。

## 安装与入口

沿用主项目的原生插件机制，新增 `screenshot` id。默认未安装，不注册 Alt+A、不预热图形设备、不创建截图 WebView、不加载 OCR 模型。已安装后，卡片显示独立开关、设置和卸载；关闭或卸载不改变翻译、剪贴板、天气等其他功能的开关。关闭插件会关闭它的截图、贴图、OCR 和翻译结果窗口，并释放可回收资源；偏好保留，重装恢复。

本分支的原生代码随主程序交付，安装沿用现有原生插件的安装记录与启用机制，未发布额外的下载包。正式市场发布仍需按主项目规范适配和审核。

首次安装或从卡片启用时，若热键注册失败，自动进入截图设置，顶部持续提示“截图已安装，需要设置快捷键”，显示失败的组合、实际原因与暂未启用状态。点击“更换快捷键”直接开始录入，成功后自动启用；也可选择“不用全局快捷键，启用截图”。退出当前页再返回时仍保留未解决的提示，处理成功后移除。不使用会自动消失的通知，也不叠加模态弹窗。（用户反馈：不能让人猜测为何开关没有启用）

## 生命周期与资源预算

- 未安装、关闭：没有注册中的截图热键，没有截图/贴图 WebView，不加载截图 D3D 设备和 OCR 会话。
- 开启但空闲：仅监听系统热键消息，不通过循环轮询按键。曾使用过的轻量消息线程可阻塞等待；不承诺整个 Fly Island 的 CPU 为零。
- 截图：按需创建隐藏窗口，等前端订阅完成、窗口定位完成、底图与遮罩提交后才显示。使用就绪握手，首次加载也不会丢掉第一次按键。
- 连续截图：复用窗口；结束后 30 秒没有新截图则销毁它。超时回收前再次检查会话和修订号，不能关闭正在使用的窗口。
- 抓屏设备：首次需要时创建；15 秒空闲或插件停用时在线程内释放 D3D 对象。释放后等待请求，不做周期性空转。
- OCR：首次识别才加载两个模型；限制每个会话的计算线程，并关闭等待任务时的自旋。最后一次识别完成后空闲 60 秒释放模型会话；正在进行的识别通过引用持有模型，避免中途释放。关闭插件清空缓存，已在执行的操作完成后释放其引用。
- 一帧 3840×2160 的 RGBA 数据约为 31.6 MiB，画布与渲染层还会有额外副本，因此缓存必须有生命周期；不能靠永久预建多个全屏窗口换取速度。

30/60 秒是本阶段的平衡默认值，真实内存峰值、OCR 延迟和不同显卡表现仍需实测。OCR 限制线程和关闭自旋的设计依据见 [ONNX Runtime 线程管理](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)。

## 预留协议 v1

原生命令与前端类型化封装一一对应：

- `screenshot_capabilities()` → `{ version: 1, screenshot: true, scroll: false, recording: false }`。
- `screenshot_start_task(mode)`，`mode` 为 `screenshot | scroll | recording`；后两种明确返回“开发中”，不会分配捕获设备。
- `configure_screenshot_plugin(enabled, shortcut)` 管理功能生命周期和实际热键；空字符串仅停用全局热键，仍可点立即截图。功能关闭时释放插件窗口和缓存。
- `screenshot_ready()` 只允许截图窗口调用，完成首次加载握手。已有 `screenshot_open`、窗口 label、事件和其他命令继续兼容。

偏好保存在 `fly-island-screenshot-settings`；安装和停用记录沿用 `fly-island-native-plugins` / `fly-island-native-plugins-disabled`。不新增密钥，不改变已有数据结构；长截图与录屏暂不写可启用的偏好。

## 长截图的下一阶段

优先手动滚动捕获，再做可中止的自动滚动。复用现有选择区域与导出，不对每帧 OCR；按变化和滚动结果捕获，增量匹配接缝，去掉固定页头/页脚。采用分块拼接和临时文件，限制总像素与临时空间，避免整张巨图反复复制到前端。提供预览、撤销最后一段、完成和取消；失败时保留已获取片段供用户处理。能力实现并验证后才开放开关。

## 录屏的下一阶段

建议采用 Windows.Graphics.Capture 获取屏幕或窗口帧，原生编码管线优先系统硬件编码器；设备不支持时再说明并降级。默认建议 MP4/H.264、30fps、最高 1080p，允许用户选择更高画质。视频持续写文件，队列限制为少量帧，处理跟不上时丢弃过期帧并保持时间戳，不能在内存里积累整段录像。界面只接收状态与进度，不传每帧像素。麦克风和系统声音独立选择，默认关闭；停止、取消和异常退出均关闭设备并处理临时文件。

这些是后续设计建议，尚未实现；平台能力参考 [微软屏幕捕获说明](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture)、[捕获画面编码为视频](https://learn.microsoft.com/en-us/windows/uwp/audio-video-camera/screen-capture-video) 和 [Media Foundation 硬件转换](https://learn.microsoft.com/en-us/windows/win32/medfound/hardware-mfts)。
