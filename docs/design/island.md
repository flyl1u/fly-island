## 外形（2026-11-10 重做，同日按用户反馈再改）

默认外形保持不变；贴顶时另提供可选的内凹贴边圆角，默认关闭。（用户要求 2026-11-13：11-10 去掉肩膀的决定改为可选，不恢复旧版常开的肩膀）

- **贴顶（默认）**：顶边与屏幕上沿齐平，底部两角圆角；两侧顶端是直角，不再有内凹的"肩"。（用户要求 2026-11-10：不要贴边圆角）
- **贴边圆角（可选）**（用户要求 2026-11-13）：外观 → 外形增加「贴边圆角」，默认关闭；开启后缩进显示「圆角大小」4–20px、默认 10px，按当前岛屿缩放应用。仅贴顶且未贴边隐藏时显示，浮起和三种贴边隐藏均隐藏。使用独立、不可点击的装饰子元素，避开热区 `::before` 和描边 `::after`；左右位置由岛身实际宽度决定，肩膀大小同曲线过渡。经典模式继承岛身全高度背景，保留透明度；暂停开放的玻璃渲染器在开启肩膀时共用顶部平色和模糊，折射从下方淡入，防止接缝色差。顶部 30px 描边淡出保持不变。舞台 820px 足够：展开最大 560×1.2＋两侧20×1.2＝720px；折叠最大 480×1.4＋两侧20×1.4＝728px。
- **离开顶边（拖到别处）**：岛浮起来，四角一样圆：收起时是胶囊，展开时四角都是展开态的半径。拖回顶边 16px 以内吸附并恢复贴顶外形。
- **曲线：苹果的连续圆角**（用户要求 2026-11-10：上一版 superellipse(1.3) 不好看，改成 Apple 圆角）。苹果的圆角（Figma 里 60% 的 corner smoothing）在离角 1.6R 处就开始弯，和直边相接处没有"折"。CSS 用 `corner-shape: superellipse(1.6)` 配 1.4R 的 `border-radius` 来画，和苹果的曲线相差不到 R 的 1%（数值拟合得出，`features/appearance/cornerShape.ts`）。原生点击区域按 |x|ⁿ + |y|ⁿ ≤ rⁿ（n = 2^1.6）判断（`island/state.rs`）；上下圆角加起来超过高度时，和 CSS 一样按比例缩小（浮起的收起态因此是胶囊）。
- **半径**：相当于 30px 的苹果圆角，即展开态 `border-radius` 42px；收起态按 12 / 30 的比例为 16.8px（用户要求 2026-11-11：原来 22 / 30 时收起态就是一颗胶囊，太圆；Rust 的点击范围 `COLLAPSED_RADIUS` 同步改为 12）。收起 ↔ 展开时半径随宽高一起过渡（时长和曲线见下一条）。
- **展开、收起的动效**（2026-11-10，用户要求"优化岛屿展开丝滑度"）：宽、高、圆角用弹簧曲线（CSS `linear()` 采样阻尼弹簧，从静止起步，第一帧来晚也不会"跳"一下）。展开 560ms，带 0.8% 的回弹，像岛自己稳住；收起 380ms，临界阻尼，更快、不回弹（每个状态用"进入它"的那条曲线）。页面内容在展开开始 120ms 后淡入（240ms），6px 的下落用同一条弹簧。`@supports` 检测 `linear()`，支持时保留原采样曲线；旧 WebView2 回退为展开 `cubic-bezier(0.34, 1.3, 0.64, 1)`、收起 `cubic-bezier(0.16, 1, 0.3, 1)`，时长不变。测量：`node scripts/measure-island-motion.mjs [次数] [--scale=1.1] [--trace] [--profile] [--frames]`（生产构建、无头浏览器、CPU 降速 4 倍；开合之外也测翻页，`--trace` 连同栅格线程和 GPU 进程一起统计）。原生端本来就是"先放大窗口、动画结束后 600ms 再缩小"，一次只发一个原生调用（bb1e8de）。
- **所有用户完整播放**（老板确认于 2026-11-13）：系统关闭动画效果或要求减少动画时，外形展开 560ms / 收起 380ms、折叠条和展开面板进出、翻页淡入（220ms）、贴边收起与滑出，均与正常模式一致。很多用户关闭系统动画只是为了性能，并不是对动效敏感。此例外只覆盖岛的展开、收起相关动效，待办、消息卡片、设置页、页面入口的 Dock 跟随和玻璃光晕等仍遵守减少动画。
- **动效只动外形，不重画内容**（2026-11-11，用户反馈 3.0.0 展开、翻页"巨卡"，要求"一定要丝滑"）：每帧只改岛外形（`.island`）的宽、高和圆角，尺寸直接按缩放算成 px；里面的折叠条和页面面板各自保持固定的 `scale()`，缩放本身永远不做动画。页面面板在变形期间（展开、收起、翻页、页面高度变化，约 640ms，`useMotionLayer.ts`）临时拥有自己的合成层，只被移动、淡入淡出和裁切，不再每帧重新绘制整页的文字、额度环、封面模糊；动完撤掉合成层，文字重新直接画在岛上。翻页时面板立刻换成新页面的高度（只排版一次），由外形的高度过渡把它露出来或收进去，不再每帧重排整页（以前文件中转的文件名测量每帧都会触发一次 React 渲染）。变形期间，会带动整岛重渲染的轮询（媒体状态、Agent 状态与会话、音频电平）跳过这一拍（`lib/islandMotion.ts`）；展开后不显示波形，音频电平也不再轮询。
- **描边**：展开态有一圈 1px 的淡白描边（`.island::after`），让黑色的岛在深色窗口前也有边界；贴顶时描边在顶部 30px 内淡出，屏幕边缘就是岛的上沿。收起态没有描边，也没有任何白线：贴边隐藏时不画提示横条；用鼠标点过收起岛上的按钮后不留底边亮线，只有键盘焦点才点亮。（用户要求 2026-11-10：收起时不要白线）
- **内层同心**：页面面板与岛边缘相距 20px，圆角取"岛屿圆角 − 20px"，形状同为连续圆角；收起态焦点框内缩 3px 跟随小岛圆角。`tests/regression/island-tour.html?test=1` 逐页检查内容没有超出岛的圆角形状、也没有挤到距岛边缘 8px 以内。
- **岛内的方框也用连续圆角**（2026-11-10，用户要求：岛里的框要苹果的圆角，待办的圆角不好看）：待办条目、输入框、笔记本页签、卡片、剪贴板行和缩略图、翻译框、消息与邮件、音乐封面、文件中转、岛内设置页的分组卡片和控件，都和岛同一条曲线。`tokens.css` 里一套刻度 `--corner-xs / sm / md / lg / xl / 2xl`（苹果半径 4 / 6 / 8 / 10 / 12 / 16），和 `corner-shape: var(--corner-shape)` 成对使用；支持 `corner-shape` 时按 1.4 倍半径画 superellipse(1.6)，不支持时退回同样大小的普通圆角（岛本身也一样退回 42 / 1.4 = 30px 的圆角），尺寸和嵌套不变。原来散落的 4–18px 圆角按就近刻度换成这些 token。胶囊（按钮、页面圆点、开关）和圆形保持正圆：superellipse 会把它们的两端压方。嵌套规则：里面的框圆角 = 外框圆角 − 两者间距（CSS 半径），不小于 `--corner-xs`；面板用 `--island-panel-radius`，面板里贴着 16px 内边距的框可用 `--island-card-radius`。Agent 页的样式（另一个会话负责）暂时还是旧的 `--radius-*` 普通圆角，之后换成同一套 token 即可。
- 待办：页签四角同一个圆角（原来上 7 下 4 的不对称圆角加一条底影）；条目列表不再比上面的输入框窄 4px（滚动条的位置改用负外边距让出）。
- 旧设置里的 `islandCornerRadius`、`islandCornerShape` 照旧不读取（按默认值），localStorage key 不变。
- 调研与对比页见 `docs/investigations/corner-shape-compare.html`（当时比较了圆角与 squircle）。

## 灵动岛视觉规范（2026-11-06）

- 展开顶栏的六个页面入口在「外观 → 风格 → 页面按钮」切换胶囊或图标，默认胶囊。（用户确认）图标沿用 16px 线条和各页面的颜色，选中时有轻底和细描边。Agent 图标保留状态色。（Agent 推断）

下列条目除注明"用户确认"外，均为 Agent 推断，依据一轮岛屿界面的设计审阅。圆角形状见上文"顶边贴合"。设置窗口不在这一轮范围内。

- **清晰度**：新用户默认折叠 / 展开缩放都是 1.0（老用户保留已存值）。不常驻 `will-change`：页面面板只在变形期间临时提升为合成层（见"动效只动外形"）。缩放用 `transform`（不用 `zoom`），因为原生点击区域（`island/passthrough.rs`）按"基准尺寸 × 缩放、顶部居中"计算，`zoom` 会改变布局盒、还会让展开高度测量换算；2026-11-11 起缩放放在折叠条和页面面板上，外形本身按缩放后的 px 尺寸画。进场动画用 `backwards` 填充，结束后不残留合成层。
- **字体**：全岛一个字体栈 `--font-ui`（`Segoe UI Variable Text`、`Segoe UI`、`Microsoft YaHei UI`…），写在 `tokens.css`，`base.css` 引用；不再有私有字体栈和 `font-synthesis: weight`（像素字体主题除外）。字重只用 400 / 600，≥15px 的标题可用 700；不用 800 / 900。
- **文字 4 级**：`--text-1/2/3` 与 `--text-placeholder`，同一色相（`--color-text` 的 248,246,240）取 .96 / .68 / .54 / .42。在岛 `#030303` 与内层面板 `#1e1e22` 上分别为 17.5 / 14.2、8.7 / 7.8、5.7 / 5.4、3.8 / 3.8：前三级用于可读文字（≥4.5:1），placeholder 只给输入框占位。岛上中性灰文字一律用这 4 级，带色相的强调色（薄荷、粉、紫等）不在此列；待办纸张上的墨色不在此列。
- **图标**：岛上 lucide 图标只用 16px（顶栏、折叠条、列表）和 14px（行内、插件页按钮），统一 `strokeWidth={1.5} absoluteStrokeWidth`；品牌图标 16px。
- **颜色语义**：颜色只给数据和状态用，其余黑白灰。黄色只表示"需要注意"（Agent 状态）；剪贴板页圆点和玻璃强调色改为粉 `#f4a7c4`，"有新版本"徽标和设置按钮上的提示点改用强调青 `--color-accent`。会话列表里仍有运行中会话时，状态灯显示蓝色运行，不再出现"绿灯 + 蓝色数字"。
- **透明度**：经典模式的"透明度"只作用于岛的底色（`--island-fill`）和折叠态的明暗渐变（`--island-fill-alpha`），文字和图标保持不透明。有意的变化：以前整岛一起变淡，现在文字、待办纸张和内层面板在透明度 < 100 时保持不透明。（原来贴顶时用底色条盖住顶边描边、半透明时透出深线的问题，2026-11-10 改为描边在顶部淡出后不再存在。）

## 配色（2026-11-14，用户要求）

用户反馈：岛屿只有一套深色，文字颜色写死，把背景改成白色后就看不清了。

- 「外观 → 风格 → 配色」：深色（默认，就是原来的样子）、浅色、跟随系统。存在 `focusd-island-settings.colorScheme`。四个窗口都在 `<html>` 上写 `data-theme`，跟随系统时用 `matchMedia('(prefers-color-scheme: dark)')` 监听。（用户确认）
- **颜色从通道派生**：`tokens.css` 里文字是 `--ink-rgb`，半透明叠加和描边是 `--overlay-rgb`，`--text-*`、`--color-white-aXX` 都由它们算出来。组件不写死白色或深色底；只在一种配色下需要不同值的单个颜色，用 `color-mix(in srgb, 浅色值 calc(var(--is-light) * 100%), 深色值)`，阴影用 `calc(a - var(--is-light) * b)` 变淡。
- **岛屿的明暗看背景色，不看配色**：岛屿舞台带 `data-tone`，按实际背景色的亮度（`theme.ts` 的 `toneOn`，即 `inkOn` 的分界 0.18）决定用深色还是浅色那套 token。所以深色配色下把背景改成白色，文字、图标、内层面板都变成浅色版本。设置里的岛屿预览同样处理。
- **三种自定义颜色**：每种配色各有一套默认值（深色 `#2F2F37` / `#FFFFFF` / `#3AE489`，浅色 `#F4F4F7` / `#1C1C22` / `#12A155`）。存的值等于任意一套默认值，就视为「没改过」，跟着配色走；改过的值在所有配色下都保留。文字色和状态灯没改过时跟着背景的明暗走，不跟配色走。颜色设置里显示的是实际画出来的颜色。
- **浅色文字四级**：同一色相 `26,26,32`，取 .94 / .72 / .64 / .50。在岛 `#F4F4F7` 与内层面板 `#E7E7EA` 上分别为 13.5 / 12.1、6.5 / 6.2、5.0 / 4.8、3.3 / 3.2，前三级 ≥4.5:1。深色这几级不变。
- **浅色的强调和状态色**加深到能在白底上看清：强调 `#0071B8`、警告 `#9A6700`、危险 `#C7354B`；会话灯的黄色加深为 `#E5B400`，仍然只表示「需要注意」。音乐页从封面取的强调色在浅色岛上取同一色相、亮度 0.38（`artworkTint.ts` 的 `tintOnLight`）。
- 浅色岛屿在白色窗口前没有边界，展开和收起时各加一层很淡的阴影；深色不加。黑胶唱片（音乐空闲页）、二维码白底、批准按钮的白字在两种配色下保持原样。
- 设置窗口的原生标题栏和窗口底色由前端调用 `set_settings_window_theme` 设置，只改 DWM 标题栏属性和窗口底色，不改窗口主题：改窗口主题会同时改所有窗口共用的 WebView2 配置的首选配色，「跟随系统」就会读到自己设的值。启动时在首帧之前同步写 `data-theme`，窗口隐藏到页面画完再显示，不会先闪一下深色。

## 收起时的临时提示（2026-11-07）

- 收起的小岛上，消息预览之外的临时提示按这个顺序占用文字位置：设备提示（耳机或蓝牙音频连接 / 断开、蓝牙电量低、插拔电源，3 秒）先于音量 / 亮度提示（1.5 秒），二者都让位于消息预览。展开、贴边收起、游戏免打扰时不显示，期间发生的变化直接丢弃，不补显示。（Agent 推断）

- 展开、收起动画中文字保持清晰（F14）：缩放永远不做动画（2026-11-11 起连 `--island-scale` 的过渡也去掉了，见"动效只动外形"），合成器不会把位图放大缩小；面板按最终缩放栅格化一次，6px 滑入是这一层前面的 `translateY`，只在变形的约 640ms 里临时 `will-change`。以后给岛上的文字加动画时同样避免缩放过渡和常驻 will-change。（用户反馈；2026-11-11 为了丝滑改为变形期间临时提升合成层，期间文字可能是灰度抗锯齿，动完恢复）

## 收起时显示什么、页面圆点的顺序（2026-11-10，用户要求）

- **显示优先级**：收起的岛的文字位置可以显示 AI Agent 任务（运行中的会话标题）、歌词（播放时的当前一句）和待办（进行中的待办或剩余数量）。设置 → 外观 →"岛屿展示优先级"里三行可以拖动排序（也可以在每行右侧的把手上按上下方向键），几样同时有内容时显示排在最前面的。默认顺序 Agent → 歌词 → 待办：和以前一样 Agent 优先，没有运行中的 Agent 时放歌就显示歌词，否则显示待办。**待办只有"开始"了一条才按排序占位**（2026-11-11，用户要求）：待办排在 Agent 前面、又点过某条待办的"开始"时显示这条待办；没有开始任何待办时，轮播的待办标题和"剩余 N 个待办"排到最后，有运行中的 Agent 会话（或正在放的歌词）就显示它们，其他都没有内容时才显示待办。（`collapsedItem.ts`）点开收起的岛时：显示的是 Agent 任务就打开 Agent 页；显示歌词或待办时打开上次展开的那一页（不再跳到音乐页），音乐页的入口是右侧的小波形按钮。（用户要求 2026-11-10：媒体热区是波形，歌词显示时点岛应回到上次的页面）
- **歌词这一行**：当前句，句子之间和没有歌词时显示"歌名 · 歌手"；换句直接替换，不做上下动画（用户觉得岛上上下切很别扭；展开后音乐页里仍然升起）。每句提前 200ms 出现，在下一句开始的那一刻换（不再每 250ms 查一次），抵掉系统报告进度的延迟。显示歌词时岛保持最宽，不随每句长短变宽变窄；长句省略。歌词跟随音乐页的设置和这首歌自己的快慢。展开期间也预取当前歌曲歌词，仅暂停收起歌词的换句计时；收起、歌词迟到及窗口恢复时按当前时间重新定位，失败或未找到的结果在内存里保留 60 秒。（用户要求 2026-11-13）

- **岛上的排列**：设置 → 外观 →"岛上的排列"画着一个收起的岛（文字和状态图标：新邮件、置物架文件数、音乐波形、Agent 会话数或收起圆点），按住任一项左右拖动（或在它上面按左右方向键）调整位置，放在文字左边的图标显示在岛的左侧；没打开的功能显示为灰色、位置保留；右上角"恢复默认"。真实的收起岛按这个顺序排。参照岛仔（xiaotang-daozai）设置里的"常驻排列"：按住图标左右拖动、灰色图标为暂未显示的组件。（用户要求：岛屿上存在的事物支持拖拽移动；2026-11-10 确认是这个意思）
